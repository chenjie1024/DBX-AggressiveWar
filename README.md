# AggressiveWar

> 在 DBX 里征服了 SQL，为什么不来这里征服世界？

一个跑在 [DBX](https://github.com/t8y2/dbx) 里的回合制征服游戏：27 个历史文明、程序化生成的地图、会评估威胁的 AI，
以及一层**看起来像 SQL 工作台**的伪装界面。打开插件先看到的是一屏"数据库查询"，按老板键才露出地图。

| | |
|---|---|
| 插件 id | `com.xingxi.game` |
| 版本 | 0.6.1 |
| 平台 | Windows x64（含 Rust sidecar） |
| 要求 | DBX ≥ 0.6.0 |
| 权限 | 仅 `host.storage` |
| 安装包 | 约 470 KB（解包约 1.0 MB） |

---

## 背景

"攻伐战争"的设定很简单：**你是一个文明的君主，目标只有一个 —— 占领地图上的每一块区域。**

没有外交、没有贸易、没有科技树爬升，只有兵力数字与邻接关系。名字里的 *Aggressive* 是认真的：
游戏里没有防守胜利，你不打出去就永远赢不了 —— 终局条件是"占满全图"，把对手打光还不够，
剩下那些灰色中立地块也得一块块啃下来。

27 个文明取自真实历史（秦、汉、唐、罗马、迦太基、波斯、蒙古、维京、阿兹特克……），各有独立配色与图标；
5 个剧本决定可选国家池与默认地图（地球列国 / 世界地图 / 战国七雄 / 三国 / 地中海）。

## 玩法

### 一局怎么开始

菜单里选 **剧本 → 地图模板 → 国家 → 区域数 → AI 对手数 → 难度**，可开关战争迷雾，然后「开始游戏」。

- 地图规模：20 / 28 / 36 / 44 / 52 区
- AI 对手：1–5 个（联机时人类会占用 AI 席位）
- 难度：简单 / 普通 / 困难（影响 AI 进攻门槛与每区兵力加成）

### 每回合能做什么

每方每回合 **10 次行动**（调兵算 1 次、进攻算 1 次，与兵力多少无关）：

| 操作 | 说明 |
|---|---|
| **进攻** | 选中己方区域（≥ 2 兵）→ 点相邻敌方/中立区 → Risk 式骰子战斗（双方最多 3 骰，受兵力与加成限制），胜则占领 |
| **调兵** | 选中己方区域 → 点相邻己方区域 → 自选调动数量（可全部调走） |
| **侦查** | 选中己方区域（≥ 6 兵）→ 点 2 格内的敌区 → 消耗 5 兵 + 1 行动，探明目标及其相邻区的兵力 |
| **建造** | 每区每种特殊设施各可建一个：🏛️兵营（+2 产兵）/ 🛡️要塞（+2 防守骰）/ 💰宝库（+3 兵），各 1 行动 + 5 兵 |
| **结束回合** | 空格或按钮（还有行动没用完时会二次确认） |

### 地形与产出

| 区域 | 每回合产兵 | 防守骰 |
|---|---|---|
| 🏰 城池 | +4 | +1 |
| ⛏️ 矿区 | +2 | 0 |
| 🌾 农场 / 🌿 平原 | +1 | 0 |
| 🌲 森林 / ⛰️ 山地 | 0 | +1 |

### 成长与随机

- **科技政策**（按占区数自动解锁）：5 区工坊、8 区航海术（跨海不再 -1 骰）、11 区筑城术、14 区后勤（+3 行动）、18 区帝国
- **事件卡**：每 5 回合抽一张，作用于当前玩家（丰收 / 征兵 / 瘟疫 / 蛮族入侵 / 叛乱）
- **季节与天气**：影响产兵与战斗，冬天产兵 -1
- **平衡机制**：领地加成（每 4 区 +1，上限 +4）、劣势补贴（落后每区 +1，上限 +4）、占领损耗 1 兵
- **战争迷雾**（可选）：己方 + 相邻一圈可见，探索过的区域留阴影，敌方兵力显示 `?`，势力详情用 `≈` 估算

### 怎么算赢

**占领全图每一块区域**（含中立区）。全员出局则平局；回合上限 130，到点按积分排名结算（只是结算，不是胜利条件）。

## 特色

1. **确定性随机**：核心用种子随机（`mulberry32`），RNG 状态随存档保存 —— 同种子 + 同指令序列 = 逐字节相同的局面。
   这是联机锁步的基础，也是"可复现 bug"的基础。
2. **程序化地图**：6 套模板（含用经纬度多边形写的**地球真实板块**），陆地上用网格 Voronoi 切出不规则区域，
   跨大陆自动生成海路保证全图连通，57 个真实地名锚点。
3. **有性格的 AI**：按国家特质区分进攻性（蒙古 1.35 好战 / 宋 0.7 龟缩 + 防守加成），
   用"胜算 × 目标价值"多点评分，并用威胁评估把后方兵力调往最危险前线。
4. **伪装成 SQL 工作台**：这是本插件最"反游戏"的部分 ——
   - 打开即见：一屏可编辑 SQL 编辑器（**行号 + 语法高亮**）+ 结果表格（检索、复制、导出 CSV）
   - **老板键**默认 `Ctrl+Shift+Z`，在设置里点一下按钮即可按键录制改成任意组合
   - **离开工作台自动伪装**，可选"切回时也保持伪装"；伪装时标题变 DBX、冻结渲染循环、暂停音频
   - 伪装层自己的输入框能正常打字，但游戏键位被吞掉，不会误触结束回合
5. **本地局域网联机**：插件自带 Rust sidecar 当宿主 ——
   - 在本机监听端口、**托管游戏页面**，手机连同一个 WiFi **扫二维码**就能加入
   - 通道上：插件 UI 走宿主 RPC 轮询，手机页走 SSE + POST（都不依赖 WebSocket 帧）
   - 中继只转发不判定，各端本地跑规则（锁步），掉线重连自动补发历史指令追平
6. **存档自动保存**：走 DBX 的 `host.storage`，关掉插件下次打开还在。

## 安装

### 普通用户（推荐）

1. 到 [Releases](https://github.com/chenjie1024/DBX-AggressiveWar/releases) 下载
   `com.xingxi.game-<版本>-windows-x64.dbxp`
2. DBX → 插件中心 → 「安装本地包」选择该文件
3. 如果是未签名开发包，先在设置里打开「允许安装未签名开发包」
4. 装好后在插件列表里找到 **AggressiveWar**，点开即可

### 用 CLI 安装

```bash
dbx-plugin install ./com.xingxi.game-0.6.1-windows-x64.dbxp
```

### 从源码构建

需要 Node 20+、Rust stable、`@dbx-app/plugin-cli`，以及游戏源码仓库（已开源）：

```bash
git clone https://github.com/chenjie1024/aggressiveWar.git
```


```bash
# 1) 构建游戏 UI（同时把 UI 嵌进 sidecar）
GONGFA_REPO=/path/to/aggressiveWar node tools/build-ui.mjs

# 2) 编译 sidecar
cargo build --release --manifest-path backend/Cargo.toml

# 3) 打包
dbx-plugin package .
# 产物：dist/com.xingxi.game-<版本>-windows-x64.dbxp
```

本地调试：

```bash
dbx-plugin dev --path . --port 5195
```

## 使用

### 第一次打开

插件打开后**先看到的是伪装界面**（SQL 工作台），这是设计如此，不是加载失败：

1. 右上角 ⚙ → 可以改老板键、关闭"打开时先显示本界面"
2. **按老板键（默认 `Ctrl+Shift+Z`）进入游戏** —— 没有「进入游戏」按钮，伪装只能由老板键解开
3. 进入游戏后，按老板键 / 失去焦点 / 切到别的标签都会切回伪装界面；**回到工作台或点一下都不会自动露出游戏**

### 联机

1. 进入游戏 → 右下角「🌐 联机」→「启动中继」
2. 面板会显示**二维码**和局域网地址（如 `http://192.168.2.154:3000`）
3. 手机连同一个 WiFi → 扫码或打开地址 → 看到游戏首页
4. 房主在游戏菜单「本地局域网联机」里**创建房间**，把 4 位房间码告诉对方
5. 对方输入房间码加入 → 房主点「开始对局」（最多 6 方）
6. 房间码会同步显示在右下角面板上（带复制按钮），房主不用来回切菜单

## 注意事项

### 关于伪装

- 老板键默认 `Ctrl+Shift+Z`。游戏自己占用了 `空格`（结束回合）、`Esc`（取消选中）、`Tab`（切区域）、
  方向键、`Ctrl+Z`（撤销），**不要**把老板键设成这些。
- 伪装时所有按键都会被吞掉（避免老板敲空格结束回合），**只有伪装层内的输入框例外**。
- 伪装时渲染循环会被冻结、音频被暂停 —— 这是省电设计，不是卡死；切回游戏立即恢复。
- 伪装一旦显示，**只有老板键能解开**（回标签、点一下都不会露出游戏）——这样切标签回来不会"闪一下游戏"。

### 关于联机 / 防火墙

- **Windows 防火墙会拦没有放行规则的程序**：表现是端口在监听，但手机（甚至本机 curl）都连不上。
  面板里的「本机连不上」是**子进程探测**出的真实结果，不是猜的。
  解决办法：Windows 安全中心 → 防火墙和网络保护 → 允许应用通过防火墙 → 勾选 DBX（或该插件进程），
  再回面板点「重新自检」。
- 中继只在你点「启动中继」后运行；关掉插件或点「停止」后，手机上的页面即失效。
- 联机是**锁步**模式：没有服务端判定，适合熟人局，防作弊能力弱。
- 房间码只有 4 位，所以中继对每个连接限制**每分钟 5 次加入尝试**；消息积压过多时中继会主动断开该连接（宁可重连，也不让锁步带着缺口继续跑）。
- 不同设备的**视野不同**（战争迷雾各自计算），两边看到的敌方兵力可能不一致，这是正常的。

### 关于数据与权限

- 只申请 `host.storage` 一个权限；没有网络、文件系统、剪贴板、进程权限。
- 存档 / 设置 / 成就存在 DBX 的插件数据目录（`plugin-data/com.xingxi.game`），卸载时由 DBX 清理。
- 当前版本只有一个**自动存档槽**：手动「保存」会覆盖上一次，没有多槽位与导出（在计划中）。

### 关于平台

- **只有 Windows x64**：sidecar 是 Windows 原生服务（监听端口 + 托管页面），macOS/Linux 上无法运行，
  因此不发布对应包，商店里也不会出现。
- 需要 DBX ≥ 0.6.0（`host_api: 1`）。
- 游戏内英文界面尚未完成，当前界面为中文。

### 关于性能

- 地图用 Canvas 2D 绘制，正常 60fps；区域数选到 52 时首帧会稍慢。
- 插件面板很窄时，开始菜单会自动回落成单列。

## 开发

```
├─ manifest.json          # 插件身份 + 工作台/命令贡献
├─ dbx-plugin.toml        # 打包范围（assets + ui），声明 Rust 后端
├─ ui-src/plugin-shim.js  # 适配层：localStorage→host.storage、伪装层、老板键、联机桥
├─ ui/                    # 构建产物（提交进仓库，CI 直接打包）
├─ backend/               # Rust sidecar：LAN 中继 + 页面托管 + 二维码
├─ tools/
│  ├─ build-ui.mjs        # 从游戏仓库构建 UI → ui/，并生成 backend/src/assets.rs
│  ├─ gen-assets.mjs      # 把 ui/ 嵌进 sidecar
│  ├─ test-shim.mjs       # 适配层单测（假宿主 + node:vm）
│  └─ lan-smoke.mjs       # 手机侧中继冒烟测试（SSE + POST）
└─ .github/workflows/     # 复用 t8y2/dbx 的 plugin-release 工作流
```

测试：

```bash
# 适配层
node tools/test-shim.mjs

# sidecar（中继协议、二维码、MIME）
cargo test --manifest-path backend/Cargo.toml
```
